# AI Interview — Product Memo

**提交版本：2026-08-30 | 公网产品：<https://ai-interview.site> | GitHub：<https://github.com/jywang001/AI-Interview>**

> 为准备大厂 AI 算法岗与 AI 应用开发岗实习面试的本科生，提供一条“材料确认—真实追问—证据复盘”的训练闭环；不是把 ChatGPT 套进聊天框，而是让每一轮问题、追问和建议都能回到候选人的简历、目标 JD 与回答原文。

## 1. 目标用户与核心痛点

本版刻意只服务准备大厂 AI 技术岗位面试的本科生，不同时覆盖保研、通用职场和所有技术岗位。创作者本人处于计算机专业学生的求职与升学准备场景，是首个目标用户和持续测试者；16 小时内没有完成正式外部访谈，因此不虚构“访谈了若干用户”的结论。当前判断来自本人实际准备经历、同类产品走查，以及开发过程中对真实失败案例的连续复盘；外部用户访谈是下一阶段第一优先级。

核心问题不是“没有题库”，而是练习无法形成反馈闭环：

1. 直接使用 ChatGPT 时，问题容易泛化，无法判断简历中哪段科研、项目或实习最值得深挖。
2. 面试官容易围绕一个缺口反复追问，或抛出宏大的系统设计题，却没有覆盖岗位需要的多个独立能力点。
3. 练完只得到“表达再具体一点”之类建议，缺少回答原文证据、阶段评分理由和下一次可以立即重练的问题。
4. 语音识别错误会把技术名词写错；如果用户不能提交前修正，后续评价就建立在错误证据上。

## 2. 产品设计与关键取舍

核心闭环是：上传文本型简历 PDF 与目标 JD → 模型结构化拆解并由用户确认事实 → 完成六阶段语音/文字面试 → 根据确认版回答生成证据化复盘 → 从薄弱点进入重练。

面试固定经过自我介绍、简历拷打、岗位知识、Hot 100 口述算法、岗位动机与到岗安排、候选人反问六个阶段。状态机每轮只允许 `probe / advance / finish`：算法岗优先科研、数据、模型与实验判断；应用开发岗优先相关实习、项目链路与工程取舍。岗位知识使用原创问题卡片，每个知识点最多窄追问一次；答错或不知道就记录缺口并换题，避免“认死理”。

我们刻意没有把时间投入到数字人视频、真实代码沙箱、账号系统、跨设备历史、OCR 和全双工流式语音。数字人最初很吸引人，但它不能解决训练价值问题；本版先确保没有视频时仍能从真实材料走到可执行反馈。算法环节采用 5–10 分钟独立思考与口述实现，不执行用户代码。扫描 PDF、长期数据保存和实时版定向重练不在本次范围；页面对演示数据和真实生成结果做明确区分。

## 3. 版本迭代记录

| 阶段 | 遇到的问题 | 调整与原因 |
| --- | --- | --- |
| 最初方案 | 想同时做数字人、语音和双 Agent，表现层过重 | 先冻结数字人，优先打通材料—面试—复盘闭环 |
| 面试流程 | 快速问答不像真实面试，阶段边界和结束条件模糊 | 锁定六阶段顺序，增加快速/真实模式和确定性状态机 |
| 简历解析 | 规则解析脆弱，模型引用偶尔无法与原文核对 | 改为 LLM 结构化解析、证据校验、用户确认后再进入面试 |
| 简历拷打 | 默认追第一段经历，算法岗与开发岗偏好不明显 | 按 JD 相关性、经历类型和岗位亲和度排序；算法岗偏科研，开发岗偏项目/实习 |
| 岗位知识 | 问题宏大、追问黏住同一缺口 | 引入原创问题卡片与内部评分锚点，单知识点最多追问一次 |
| 语音体验 | STT 技术词可能出错，TTS 等待像页面卡住 | 转写先进入可编辑草稿；问题先显示，加入等待计时与文字兜底 |
| 上线验证 | Alpine 提取中文 PDF 为空，容器健康检查假失败 | 补充 `poppler-data`，固定 `HOSTNAME=0.0.0.0`，并用线上 PDF、LLM、TTS→STT 闭环实测 |

## 4. 如果再给一周

第一天完成 5–8 位目标用户访谈，并把失败样例固化为回归评测；随后让定向重练完全使用实时报告数据，增加“同一问题初答—重答”的证据差异。再补充岗位知识卡片的人工审核、延迟/费用监控和失败演练。表现层最后再加入多个原创面试官 Persona 与可选数字人，前提是它不会改变核心状态机，也不会让等待时间变长。

## 5. AI 工具使用与诚信说明

- **OpenAI Codex**：在产品负责人持续决策下协助整理 PRD、实现代码、类型检查、构建、部署诊断和线上验收；关键范围、流程与取舍由产品负责人确认。
- **OpenAI-compatible GPT-5.5**：运行时用于简历/JD 结构化分析、单轮面试判断和 Coach 报告，输出必须通过 Zod Schema 与证据校验。
- **火山豆包 Seed ASR 2.0 / Seed-TTS 2.0**：用于语音转写与面试官题目播报；失败时保留文字路径。
- **开源软件**：Next.js、React、AI SDK、Zod、Poppler、ReportLab 等，版本、许可证和用途记录在 `THIRD_PARTY.md`。

项目不是从竞品仓库 fork。开发过程中查看过同类开源项目以理解产品类别和失败模式，但没有导入其代码、提示词、题库、界面、数字人或素材；本项目的流程、问题卡片、数据契约、虚构材料和 Presenter 均为独立实现，来源边界记录在 `DESIGN_PROVENANCE.md`。
