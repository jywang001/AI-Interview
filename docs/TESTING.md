# 自动化测试说明

## 快速验证

```sh
pnpm test:unit
pnpm test:all
```

`test:unit` 完全离线，覆盖材料引用核验、岗位化简历排序、六阶段契约、Hot 100 选题约束、自适应控制器和 API 错误边界。`test:all` 在此基础上继续运行 TypeScript 检查与生产构建，与 CI 一致。

## 真实模型行为评测

先在本机 `.env` 配置：

```text
OPENAI_API_KEY=...
OPENAI_MODEL=...
OPENAI_BASE_URL=... # 使用兼容端点时填写
```

然后运行：

```sh
pnpm test:ai
```

当前自动检查三项高风险行为：

1. 简历回答不完整时，追问应锚定回答而不是泛泛要求“展开讲讲”。
2. 岗位知识明确不会时，应记录缺口并换题/推进，而不是反复逼问。
3. Coach 的每个证据引用必须属于正确阶段，并且是确认版回答的逐字子串。

需要留存机器可读结果时运行：

```sh
pnpm test:ai:report
```

结果写入 `evals/results/latest.json`。该文件默认不提交，避免把本地模型信息、时间戳和临时输出混入版本库。

AI 行为具有一定非确定性。发布判断应同时保留模型名、运行时间和失败样例；不得通过放宽断言掩盖稳定失败。
